# P1 兼容性修复实施报告（2026-09-03）

## 修复概览

本次修复针对与 SillyTavern 的核心兼容性差距，完成了4个P1级别修复：

### ✅ 1. Continue续写功能（P1-2）
**问题**：无续写按钮与逻辑，`continuePrefill`开关孤立存在  
**修复内容**：
- **UI层**（`src/pages/chat/chat.vue`）：
  - 在最后一条AI消息下方增加"续写"按钮（仅当未在生成中时显示）
  - 新增 `handleContinue()` 函数：触发续写时替换（而非新增）最后一条AI消息，将原内容作为前缀传给 processor
- **引擎层**（`src/engine/MessageProcessor.ts`）：
  - `SendOptions` 新增 `continuePrefix?: string` 参数
  - 在 LLM 返回内容前拼接 `continuePrefix`（对齐酒馆 `type='continue'` 行为）
- **CSS样式**：`.continue-btn` / `.continue-text`（与 swipe 按钮保持一致的视觉风格）

**对齐酒馆行为**：
- 酒馆在 `populateChatHistory` 时检测 `type === 'continue'`，将最后一条AI消息移除并拼接 nudge prompt
- 本项目简化实现：直接在 MessageProcessor 内拼接前缀，不改变 PromptBuilder 的 messages 数组（更简洁且功能等价）

### ✅ 2. 世界书正则vars传参修复（P1-5）
**问题**：`wiRegex()` 调用时未传 `vars`，导致世界书内容中的宏替换（`{{user}}`/`{{char}}`等）与 `substituteRegex` RAW/ESCAPED 模式全部失效；atDepth条目未传 `depth`，`minDepth/maxDepth` 过滤形同虚设  

**修复内容**（`src/engine/PromptBuilder.ts`）：
```typescript
// 修复前
const wiRegex = (t: string) => applyRegexScripts(t, preset.regexScripts || [], 2)

// 修复后
const wiRegex = (t: string, depth?: number) => applyRegexScripts(
  t,
  preset.regexScripts || [],
  2,
  { vars, isPrompt: true, depth }
)

// atDepth 调用处也传入 depth
history = _insertAtDepthEntries(
  history,
  buckets.atDepth.map(e => ({ ...e, content: wiRegex(e.content, e.depth) }))
)
```

**影响范围**：
- 世界书所有 buckets（before/after/emTop/emBottom/atDepth）的内容现在可以正常解析宏
- atDepth 条目的 `minDepth/maxDepth` 过滤现在生效（对齐酒馆 `getRegexedString` 的 depth 参数语义）

### ✅ 3. 对话历史宏（P1）
**问题**：`{{lastMessage}}`/`{{lastUserMessage}}`/`{{lastCharMessage}}`/`{{firstMessage}}` 四个常用宏缺失  

**修复内容**（`src/engine/VariableEngine.ts`）：
```typescript
registerMacro('lastMessage', () => {
  const store = useRuntimeStore()
  if (!store.messages || !store.messages.length) return ''
  return store.messages[store.messages.length - 1].content || ''
})
// 同理实现 lastUserMessage / lastCharMessage / firstMessage
```

**用途**：
- 作者注/世界书条目中可使用 `{{lastMessage}}` 引用最新消息内容
- 常见用法：`{{lastUserMessage}}` 做意图解析、`{{lastCharMessage}}` 做风格一致性提示

---

### ✅ 4. H5端真实tokenizer（P1，部分）
**问题**：`countTokens` 使用启发式估算（中文1字符≈1token，英文0.25），与真实BPE token数偏差较大  

**修复内容**（`src/engine/tokenizer.ts`）：
- **H5端**：自动接入 `js-tiktoken/lite` + `cl100k_base`（GPT-3.5/GPT-4同款编码器）
- **小程序端**：保留启发式估算（受包体积限制，~22MB rank数据无法引入）
- **依赖**：新增 `js-tiktoken@1.0.21`（仅H5端加载，条件编译隔离）

**权衡说明**：
- H5 端：真实 token 计数，世界书预算分配更精确
- 小程序端：启发式估算仍够用（中文为主的 TRPG 场景下偏差可接受）
