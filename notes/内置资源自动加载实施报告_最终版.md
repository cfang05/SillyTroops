# 内置资源自动加载实施报告（最终版）

## 实施完成

已将 st_card / st_preset / st_regex 文件夹中的内置资源集成到项目中，用户无需手动导入，首次启动时自动加载到对应Store。

## 实施内容

### 1. 资源文件迁移 ✅
- **源文件夹**: `st_card/` `st_preset/` `st_regex/`
- **目标位置**: `public/assets/characters/` `public/assets/presets/` `public/assets/regex/`
- **迁移方式**: `xcopy` 命令复制（编译时自动打包到dist）
- **文件清单**:
  - 3张角色卡PNG：夏洛克·福尔摩斯_v2.png、爱丽丝·马修斯.png、尼古拉斯.png
  - 2个预设JSON：叙述思维V4-0902.json、缪斯精神预设v1.8.json
  - 1个正侧JSON：regex-双栏.json

### 2. 加载器服务 ✅
**文件**: `src/services/builtinAssets.ts`

**功能**:
- `loadBuiltinCharacters()` - 加载3张内置角色卡
- `loadBuiltinPresets()` - 加载2个内置预设
- `loadBuiltinRegexPresets()` - 加载1个内置正侧
- 条件编译隔离：H5端fetch加载，小程序端返回错误提示

### 3. Store自动加载集成 ✅

#### characterCardStore (`src/stores/characterCardStore.ts`)
- 在 `loadAll()` 时调用 `_loadBuiltinCards()`
- 检测机制：通过名称前缀 `[内置]` 判断是否已加载
- 加载逻辑：
  - 遍历内置卡列表，为每张卡添加 `[内置]` 前缀
  - 调用 `characterCardManager.createCard()` 导入
  - 重新加载卡片列表刷新UI

#### presetStore (`src/stores/presetStore.ts`)
- 在 `load()` 时调用 `_loadBuiltinPresets()`
- 检测机制：通过ID前缀 `builtin_preset_` 判断是否已加载
- 加载逻辑：
  - 遍历内置预设，为每个预设添加 `[内置]` 名称前缀
  - 生成唯一ID（`builtin_preset_` + 时间戳 + 随机数）
  - 追加到 presets 数组并持久化

#### regexPresetStore (`src/stores/regexPresetStore.ts`)
- 在 `load()` 时调用 `_loadBuiltinRegex()`
- 检测机制：通过ID前缀 `builtin_regex_` 判断是否已加载
- 加载逻辑：
  - 遍历内置正侧，为每个文件添加 `[内置]` 名称前缀
  - 生成唯一ID（`builtin_regex_` + 时间戳 + 随机数）
  - 追加到 presets 数组并持久化
  - 默认 `enabledGlobal: false`（不自动作为全局正则）

## 用户体验

### 首次启动
1. 用户打开角色卡库页面 → 自动看到3张 `[内置] xxx` 角色卡
2. 用户打开预设列表 → 自动看到2个 `[内置] xxx` 预设（不影响默认预设）
3. 用户打开正侧列表 → 自动看到1个 `[内置] regex-双栏`

### 后续使用
- 内置资源与用户导入的资源一视同仁，可正常使用、编辑、删除
- 删除后不会再次自动加载（检测机制基于"是否存在任何带 [内置] 前缀的项"）
- H5端：加载时通过 fetch 读取 public/assets/ 下的文件
- 小程序端：暂不支持自动加载（返回错误，用户需手动从相册导入）

## 技术细节

### 条件编译
```typescript
// #ifdef H5
// H5端代码：fetch + Blob/JSON解析
const res = await fetch('/assets/characters/xxx.png')
const blob = await res.blob()
// #endif

// #ifndef H5
// 小程序端代码：返回错误提示或跳过
return { error: '小程序端需手动导入' }
// #endif
```

### 重复加载防护
- **角色卡**: 检查是否存在名称以 `[内置]` 开头的卡片
- **预设**: 检查是否存在ID以 `builtin_preset_` 开头的预设
- **正侧**: 检查是否存在ID以 `builtin_regex_` 开头的正侧
- 任一条件满足即跳过加载，避免重复导入

### 异步加载
- 所有 `_loadBuiltin*()` 方法均为 async
- 使用 dynamic import 避免小程序端打包 builtinAssets.ts（条件编译内的代码不会被小程序端编译）
- 加载失败时仅 console.warn，不影响 Store 正常使用

## 已知限制

1. **小程序端不支持**：受限于 uni-app 小程序环境无法动态读取打包后的静态资源，需手动从相册导入PNG/从文件导入JSON
2. **重复检测简单**：仅检查是否存在任何内置资源，如果用户删除全部内置资源后又想要，需清除所有缓存后重新启动
3. **文件体积**：3张PNG共7.3MB，会增加H5端首次加载体积（但仅在首次访问卡库时触发fetch）

## 后续优化方向

1. **按需加载**：仅在用户访问对应页面时才加载该类型资源（目前是首次 store.load() 就加载）
2. **重新加载按钮**：在设置页面增加"恢复内置资源"按钮，删除后可一键重新导入
3. **小程序端支持**：将PNG Base64编码或转为JSON格式内联到代码中（需评估包体积影响）
4. **版本管理**：内置资源更新时能覆盖旧版本（当前实现下更新需手动删除旧资源）
