# SillyTavern 兼容性差距清单（sillytroops-uni）

> 目标：酒馆角色卡导入后能正常使用、与原酒馆无差别（已忽略群聊模式）。
> 对照：`src/engine/*` + `src/adapters/*` + `src/types/*` + `src/pages/chat/chat.vue` ↔ `referencecode/*`。
> 结论速览：**导入层已相当完整，但 Prompt 构建层是最大短板（marker 不填充 + 注入语义反了），宏系统次之。** 修好 P0 的 4 条，导入的卡即可"跑起来且内容基本一致"。

## 二、P0（致命，不修则"导入即能用"不成立）

### P0-1 ❗ marker 提示词不填充 —— 角色内容根本没进 prompt
- **ST 行为**：`PromptManager.preparePrompt` 阶段，`charDescription/charPersonality/scenario/dialogueExamples/personaDescription/worldInfoBefore/worldInfoAfter/chatHistory` 这些 `marker:true` 的占位提示词由系统填入角色卡/世界书/Persona 实际文本。
- **现状**：`PresetImporter._normalizePromptItem` 丢弃了 `marker` 字段；`PromptBuilder.buildMessages` 把 marker 当普通提示词，`content` 为空 → 被 `if (content.trim())` 静默丢弃。
- **后果**：角色卡的 **description / personality / scenario / mes_example / system_prompt 一个都不会进 LLM**。这是"不能用"的根因。
- **涉及文件**：`src/engine/PromptBuilder.ts`、`src/adapters/preset/PresetImporter.ts`、`src/types/preset.ts`。
- **修法**：加 marker 映射表，遍历 promptOrder 时按 identifier 填 `character.data.*` / persona / 世界书 / 聊天历史。

### P0-2 ❗ injection_position 语义与酒馆相反
- **ST 行为**：`INJECTION_POSITION.RELATIVE=0` = 系统块内按 prompt_order 排序（main 前后）；`ABSOLUTE=1` = 按 `injection_depth` 注入聊天历史深处。
- **现状**：`types/preset.ts` 注释与 `PromptBuilder` 把 `0` 当"按 injectionDepth 从历史末尾往前插"、`1` 当"固定前缀"。**两者行为恰好对调**。
- **后果**：导入的 ST 预设里 marker 都是 `injection_position:0`（系统块），会被你的代码当作"深度注入"错误处理；真正需要深度注入的 ABSOLUTE 提示词会被当固定前缀。
- **涉及文件**：`src/types/preset.ts`、`src/engine/PromptBuilder.ts`、`src/adapters/preset/PresetImporter.ts`。
- **修法**：统一为 ST 语义（0=系统块按 prompt_order、1=按 depth 注入历史），并保留 prompt_order 顺序。

### P0-3 ❗ mes_example 未作为 few-shot 示例注入
- **ST 行为**：`dialogueExamples` marker 由 `populateDialogueExamples` 填 few-shot（按 `<START>` 切块、`name1:`/`name2:` 行解析成 example_user/example_assistant 的 system 消息）。
- **现状**：`chat.vue._characterForProcessor()` 传了 `mes_example` 但 `PromptBuilder` 从未使用；`<START>` 切块逻辑不存在。
- **涉及文件**：`src/engine/PromptBuilder.ts`、`src/pages/chat/chat.vue`。

### P0-4 ❗ 宏语法只支持 {{name}}，无法解析酒馆宏
- **ST 行为**：`{{name::arg1::arg2}}`、list 参数、scoped `{{name}}…{{/name}}`、flags、嵌套、变量简写 `{{.var}}/{{$var}}`。
- **现状**：`VariableEngine.substituteVariables` 正则 `\{\{(\w+)\}\}`，任何带 `::` 参数的宏都不解析（`{{random::a::b}}`、`{{roll::1d20}}`、`{{setvar::x::1}}` 全部失效）。
- **涉及文件**：`src/engine/VariableEngine.ts`。

## 三、P1（高优先级，逼近"无差别"）

### P1-1 system_prompt / post_history_instructions 不注入
- ST：`system_prompt` → 覆盖 `main`（`systemPromptOverride`）；`post_history_instructions` → 覆盖 `jailbreak`。
- 现状：`CharacterImporter` 导入了，但 `chat.vue._characterForProcessor()` 只传 5 个字段，把这两者丢掉；`PromptBuilder` 无 main/jailbreak 概念。
- 涉及：`src/pages/chat/chat.vue`、`src/engine/PromptBuilder.ts`。

### P1-2 世界书注入位置硬编码，不随 prompt_order
- ST：`worldInfoBefore/worldInfoAfter` 是 prompt_order 里的 marker，位置可自由调整。
- 现状：`PromptBuilder` 硬编码 before→历史前、after→用户输入前，忽略 prompt_order 中这两个 marker 的相对顺序。
- 涉及：`src/engine/PromptBuilder.ts`。

### P1-3 世界书缺 globalScanData 的 6 个 match_* 开关
- ST：条目可勾选 `match_scenario/match_character_description/match_character_personality/match_persona_description/match_creator_notes/match_character_depth_prompt`，把这些字段文本追加进扫描文本。
- 现状：`WorldInfoEngine.buildScanTextForEntry` 只拼 `userMessage + 最近历史 + recurseBuffer`。勾了这些开关的条目**永远不触发**。
- 涉及：`src/engine/WorldInfoEngine.ts`、`src/types/character.ts`（类型里也没有这 6 个字段）。

### P1-4 世界书 AN/EM/outlet 桶未真正注入
- ST：AN（作者注上/下）、EM（示例消息上/下）、outlet（自定义出口）都是真实注入点。
- 现状：`dispatchToBucket` 收集了 `anTop/anBottom/emTop/emBottom/outlet`，但 `PromptBuilder` 只注入 before/after/atDepth，其余只打日志（代码注释明确"预留"）。
- 涉及：`src/engine/WorldInfoEngine.ts`、`src/engine/PromptBuilder.ts`。

### P1-5 世界书内容未走 WORLD_INFO 正则
- ST：条目内容在分桶后 `getRegexedString(placement=WORLD_INFO=5, isPrompt:true)`。
- 现状：`RegexScriptEngine` 定义了内部 placement=2（世界信息）映射，但 `PromptBuilder` 从未对世界书内容调用。
- 涉及：`src/engine/PromptBuilder.ts`、`src/engine/RegexScriptEngine.ts`。

### P1-6 作者注（Author's Note）整体缺失
- ST：`note_prompt/note_interval/note_depth/note_position/note_role` + 角色注，位置 IN_PROMPT/IN_CHAT/BEFORE_PROMPT，频率按消息数取模。
- 现状：完全不存在（仅世界书 an_top/an_bottom 桶预留）。
- 涉及：无对应文件，需新建。

### P1-7 Persona 描述不注入 prompt
- ST：`personaDescription` marker 在 IN_PROMPT 位置注入 persona 描述。
- 现状：`chat.vue._buildBaseVars()` 把 persona 描述放进 `{{persona}}` 变量（语义对），但若预设的 `personaDescription` marker 为空，persona 描述不会进 prompt。
- 涉及：`src/engine/PromptBuilder.ts`、`src/pages/chat/chat.vue`。

### P1-8 Markdown 渲染缺失
- ST：Showdown（粗体/斜体/列表/引用/表格/下划线）+ 引号 `<q>` 增强 + DOMPurify。
- 现状：自定义 `BlockParser` 只解析游戏标签（`<branches>/<meow_FM>/<time_format>/html/damage/台词/叙事`），**没有 Markdown**。角色卡对话里最常见的 `*动作*`、`**强调**`、列表、引用都不渲染。
- 涉及：`src/engine/BlockParser.ts`、`src/components/render/*`。

### P1-9 深度提示词 depth_prompt 不注入
- ST：`extensions.depth_prompt{prompt,depth,role}` 按 depth 注入聊天。
- 现状：类型里有，`chat.vue._characterForProcessor()` 没传，`PromptBuilder` 没注入。
- 涉及：`src/pages/chat/chat.vue`、`src/engine/PromptBuilder.ts`。

### P1-10 变量宏全家缺失
- ST：`setvar/getvar/incvar/decvar/addvar/hasvar/deletevar` + 全部 global 版（及 varexists/flushvar 别名）。
- 现状：只有 `VariableEngine.setVar/getVar` API，无宏语法、无 inc/add/has/delete。
- 涉及：`src/engine/VariableEngine.ts`。

## 四、P2（中优先级，体验/边界差距）

- **P2-1 核心宏缺失**：`time/date/isotime/isodate/random/pick/roll/space/newline/trim/if/else/original/charIfNotGroup/mesExamples/greeting/lastMessage 系列`。现有 `macros.js` 是 TRPG 语义（char/user/hp/mp…），chat 链路未接入。
- **P2-2 正则函数替换缺失**：`{{match}}`→`$0`、`$<name>` 具名组、捕获值 trimStrings 宏展开。现状只有 `$1` 静态替换。
- **P2-3 正则 minDepth/maxDepth/substituteRegex/markdownOnly/promptOnly/runOnEdit 未实现**：`PresetImporter` 导入了字段，`RegexScriptEngine` 只用 disabled/placement/findRegex/replaceString/trimStrings。
- **P2-4 Text Completion / instruct 模式缺失**：只有 messages 数组一条路径。
- **P2-5 无真实 SSE 流式**：`MessageProcessor._simulateStream` 是打字机模拟，`client.js` 一次性返回全文。
- **P2-6 无 tokenizer**：`WorldInfoEngine.estimateTokens`（中文=1/其它=0.25）粗略估算，无真实 token 计数。
- **P2-7 squash_system_messages / continuePrefill / namesBehavior 只导入未实现**：`namesBehavior` 只实现 CONTENT=2。
- **P2-8 V3 角色卡 + assets + {{asset::}} 缺失**：`CharacterImporter` 硬编码 `spec:'chara_card_v2'`。
- **P2-9 世界书四源只支持角色卡内嵌**：ST 还有全局世界书 / 聊天世界书 / persona lorebook。
- **P2-10 chat_metadata 缺失**：`conversationManager` 只存 messages/localVariables/worldInfoState/presetId 等，无 ST 的 tainted/scenario/system_prompt 覆盖/chat_id_hash/pick_reroll_seed。
- **P2-11 生成参数映射不完整**：缺 repeat_penalty/top_a/typical/stopping strings/logit_bias/CFG（对 OpenAI 兼容接口影响较小）。

## 五、P3（低优先级 / 平台限制 / 远期）

- **P3-1 斜杠命令**缺失（`/send /swipe /gen /setvar /note` 等）。
- **P3-2 扩展系统**缺失（有 `pluginStore/moduleStore` 雏形，但非 ST manifest+事件机制）。
- **P3-3 标签系统**缺失（`data.tags[]` 导入了，无全局标签/文件夹/过滤）。
- **P3-4 系统消息/旁白**缺失（`system_message_types`）。
- **P3-5 PNG 解析无魔数校验、iTXt 压缩/UTF8 标志未处理**（对 chara 的 base64 ASCII 通常无碍，但对 UTF8 直接文本的 iTXt 会错）。
- **P3-6 小程序端无法导入 PNG**（平台限制，已用 `#ifdef` 隔离，属可接受）。
- **P3-7 min activations / scan skew**（世界书最小激活数机制）。

## 六、建议实施顺序

1. **P0-2 → P0-1 → P0-4 → P0-3**（先正注入语义，再填 marker，再升级宏语法，再补 few-shot）。这四条做完，导入的卡就能跑出"内容基本一致"的对话。
2. 然后 **P1-1/2/9**（system_prompt、世界书随 prompt_order、depth_prompt）—— 让"角色人设"完整进入上下文。
3. 再 **P1-3/4/5**（世界书补全）与 **P1-10**（变量宏），世界书类角色卡基本无差别。
4. 之后 **P1-6/7/8**（作者注、persona 注入、Markdown 渲染）—— 体感上的"无差别"。
5. 最后按需推进 P2/P3。

> 注：P0-4（宏语法）+ P1-10（变量宏）本质是同一件事——把 `VariableEngine` 从"正则单层替换"升级为"支持 `::` 参数 + 注册表 + 变量宏/核心宏"的小型宏引擎（可参考 referencecode 的 `macros/engine/*` 但不需要 chevrotain，手写解析即可覆盖 90% 场景）。
