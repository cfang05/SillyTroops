# 合并方案 · 逐文件拆解清单

> 两件事：**(一) 从 game.vue 拆组件** 与 **(二) TRPG 存储重键化**。
> 阅读结论先行：4 个模块组件（CombatPanel / CharacterStatus / InventoryPanel / DiceRoller）**已经存在**，且是纯展示组件（只 emit 事件、不 import 业务 manager）。所以"拆组件"不是"新建组件"，而是**把 game.vue 里的状态逻辑迁到 chat.vue（或 composable），再接到这 4 个现成组件上**。战斗态/物品态没有独立 storage key，重键化真正落点是 stateManager + adventureManager + character-manager + App.vue。

## 二、TRPG 存储重键化（逐文件）

### 2.1 `utils/engine/stateManager.js`（51KB，1574 行）
- **现行 key**（L94）：`getStateKey() → GAME_STATE_${currentStoryId}_${currentCharacterId}`；`currentStoryId` 默认 `'tavern-mystery'`、`currentCharacterId` 默认 `'default'`（L85–86）。
- **旧键迁移**（L831 `migrateFromOldKey`）：从 `storage.STORAGE_KEYS.GAME_STATE`（=`'game_state'`）迁到新键。
- **状态结构**（`initialState`，L18–79）：`scene/trust/items/legendaryItems/flags/npcCooldown/npcCustomAliases/lastNPC/character{hp,mp,san,maxHp,maxMp,maxSan,base六维,equipment,equipBonus,effective六维,activeBuffs,activeDebuffs,statusEffects,isDying,deathSave*}`。
- **重键方案**：`setCurrentStory/Character` 改为 `setCurrent(cardId, personaId)`，key → `TRPG_${cardId}_${personaId}`；或更彻底地把 `state.character` 迁入 conversationManager 的 `trpgState`。
- **改造点**：`setCurrentStory`（L102）、`setCurrentCharacter`（L112）、`getStateKey`（L94）、`migrateFromOldKey`（L831）。

### 2.2 `utils/adventure/adventureManager.js`（290 行）

## 三、战斗 NPC 数据源改造（配套）

- 新增 `utils/combat/parseCombatTag.js`：解析世界书条目内容里的 `[combat]` 标签行（如 `[combat] hp=30 ac=13 dmg=1d8 ...`），产出结构化 `NPCDef`。
- `combatManager.getNPCDef(npcId)`：`story.npcs[npcId]` → `characterCardStore` 世界书里按键匹配 NPC 条目 + `parseCombatTag`。
- `enemyGenerator`：从 `story.npcs` 列表改为遍历世界书 NPC 条目。
- 注意：战斗开始时 NPC 数值需**直查**（不能依赖"扫描激活"），因为非 constant 条目平时不注入。
