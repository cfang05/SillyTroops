## 1. 宏系统整体架构（处理流水线）

```
┌──────────┐   ┌──────────┐   ┌───────────────┐   ┌─────────────┐   ┌───────────┐
│ 文本输入   │ → │ MacroLexer│ → │ MacroParser    │ → │ MacroCstWalker│ → │MacroRegistry│
│(string)   │   │ (词法分析) │   │ (语法分析→CST) │   │ (CST 解释执行) │   │ (查定义/执行) │
└──────────┘   └──────────┘   └───────────────┘   └─────────────┘   └─────┬─────┘
      ↑                                                                     │
   MacroEngine.evaluate(input, env) ── 编排者：pre-processors → 流水线 → post-processors
      ↑                                                                     ↓
   MacroEnvBuilder.buildFromRawEnv(ctx) ── 构建环境对象 env（names/character/system/functions…）
```

- **MacroEngine（引擎门面）**：`evaluate(input, env, {contextOffset})` 是唯一入口。
  1. 先跑 **pre-processors**（旧语法兼容改写，如 `<USER>` → `{{user}}`、`{{time_UTC-10}}` → `{{time::UTC-10}}`）；
  2. `MacroParser.parseDocument()` 得到 CST（词法/语法错误只告警不中断）；
  3. `MacroCstWalker.evaluateDocument()` 遍历 CST、求值所有宏；
  4. 最后跑 **post-processors**（解除 `\{ \}` 转义、清除孤立 `{{trim}}`、清理 `{{else}}` 标记）。
- **MacroLexer（词法）**：基于 Chevrotain 的 **模式（mode）状态机**。从 `plaintext` 模式遇到 `{{` 进入 `macro_def`，按上下文在 `macro_identifier_end` / `macro_args` / `macro_filter_modifier(_end)` / `var_identifier` / `var_after_identifier` / `var_value` 各模式间切换；参数内部允许嵌套宏（重新进入 `macro_def`）。`ModePopper` 兜底弹出模式，避免非法输入导致 lexer 崩溃。
- **MacroParser（语法）**：Chevrotain `CstParser`，产生 CST。核心规则：`document` → 若干 `macro`/`plaintext`；`macro` = `{{` + 可选 flags +（`variableExpr` 变量简写 | `macroBody`）；`macroBody` = 标识符（含 `//` 注释宏）+ 可选 `arguments`；`arguments` = `::` 分隔列表，或单个 `:` + 允许含 `::` 的参数。开启完整位置跟踪与错误恢复。
- **MacroCstWalker（求值）**：纯 JS 递归遍历 CST，把每个宏节点翻译成 `MacroCall`（含 `name/args/flags/isScoped/rawInner/rawWithBraces/rawArgs/range/globalOffset/cstNode/env`），调用 `resolveMacro`（引擎的 `#resolveMacro`）→ 最终落到 `MacroRegistry.executeMacro()`。变量简写在此直接调用变量 API 求值。
- **MacroRegistry（注册表）**：`Map<小写宏名, MacroDefinition>`。存宏定义元数据 + `handler`，执行时做参数个数/类型校验，构造 `MacroExecutionContext` 传给 handler，并对返回值做 `normalize`（统一转字符串）。
- **MacroEnvBuilder（环境构建）**：把 `substituteParams` 的原始上下文（content / name1 / name2 / original / group / replaceCharacterCard / dynamicMacros / postProcessFn）构造成 `MacroEnv`；支持扩展 `registerProvider(provider, order)` 注入额外字段。

### 关键对象与枚举（思维导图节点）

| 对象 | 要点 |
|---|---|
| `MacroEnv` | `content`（整段原文）、`contentHash`（`getStringHash(content)`）、`names{user,char,group,groupNotMuted,notChar}`、`character{...懒加载字段}`、`system{model}`、`functions{original 一次性, postProcess}`、`dynamicMacros{}`、`extra{}` |
| `MacroCall` | 一次宏调用：`name`、`args[]`（已求值）、`flags`、`isScoped`、`rawInner`、`rawWithBraces`、`rawArgs[]`（未求值原文）、`range`、`globalOffset`（原文档绝对偏移，用于 `{{pick}}` 确定性种子）、`cstNode`、`env` |
| `MacroExecutionContext`（handler 收到的参数） | `name`、`args`、`unnamedArgs`、`list`（list 参数，无则 null）、`namedArgs`（**预留，当前恒为 null**）、`flags`、`isScoped`、`raw`、`rawOriginal`、`rawArgs`、`env`、`cstNode`、`range`、`globalOffset`、`normalize`、`trimContent`、`resolve(text,{offsetDelta})`（延迟求值用）、`warn` |
| `MacroCategory` | `utility / random / names / character / chat / time / variable / prompts / state / misc / uncategorized` |
| `MacroValueType` | `string / integer / number / boolean`（同时用于参数类型校验与返回类型标注） |

### MacroRegistry 注册结构（`MacroDefinitionOptions`，全部字段）

- `name`（标识符，须匹配 `/^[a-zA-Z][\w-_]*$/`；`//` 特例允许作为注释宏）
- `aliases`：`[{alias, visible}]`，别名共享同一定义（默认可见）
- `category`：MacroCategory 或自定义字符串
- `unnamedArgs`：数字（全部必填）或数组 `[{name, optional, defaultValue, type, sampleValue, description}]`；可选参数必须是后缀
- `list`：`true`（任意数量）或 `{min, max}`；list 参数排在 unnamed 之后
- `strictArgs`（默认 true）：参数不合规时抛错 vs 仅警告
- `description` / `returns` / `returnType` / `displayOverride` / `exampleUsage`
- `delayArgResolution`（默认 false）：为 true 时参数中的嵌套宏**不**预先求值，handler 拿到原文后自行 `resolve()`（如 `{{if}}` 只求值命中分支）
- `handler(context) => string`

执行时：`isArgsValid` 校验个数（含 list 的 min/max）→ `validateArgTypes` 按类型定义校验（integer 正则 / number 可解析 / boolean 用 isTrueBoolean/isFalseBoolean）→ 调 handler → `normalize` 结果。

### 动态宏（dynamicMacros，一次求值会话内有效）

`env.dynamicMacros`（key 转小写）优先于注册表，三种格式：
1. 字符串 → 直接值（无参）；
2. 函数 → handler（legacy 兼容，无参）；
3. `MacroDefinitionOptions` 对象 → 完整定义（可带参数/类型校验）。

### 错误处理（MacroDiagnostics）

- `createMacroRuntimeError`：`MacroRuntimeError` 类型错误，引擎捕获后仅记警告、**保留宏原文**；
- `logMacroRuntimeWarning` / `logMacroInternalError` / `logMacroRegisterWarning/Error` / `logMacroSyntaxWarning`（词法/语法阶段，带行列位置）/ `logMacroGeneralError`；
- `onboardingExperimentalMacroEngine`：向未开启新引擎的用户弹窗引导启用。

### 环境对象 env 的细节

- `names.user/char` 来自 `name1Override ?? name1`、`name2Override ?? name2`；
- `names.group`（含静音成员）、`names.groupNotMuted`（不含）、`names.notChar`（除当前说话者外的所有参与者 + 用户）由 `groupOverride` 或群组 members 计算；
- `character` 字段（`replaceCharacterCard` 时）为**懒加载 getter**：charPrompt(system)、charInstruction(jailbreak)、description、personality、scenario、persona、mesExamplesRaw、version、charDepthPrompt、creatorNotes、firstMessage、alternateGreetings；
- `functions.original` 一次性：首次调用返回 original 文本，之后返回空串（与 legacy `{{original}}` 一致）；
- `dynamicMacros` 键统一小写。

## 2. 宏语法完整说明

### 2.1 基本形式

| 形式 | 示例 | 说明 |
|---|---|---|
| 无参 | `{{char}}` | 最简形式 |
| 单参（空格） | `{{roll 1d20}}` | 标识符后空格 + 参数 |
| 单参（单冒号） | `{{reverse:I am Lana}}` | 兼容旧 `{{name:arg}}` 风格 |
| 单参（双冒号） | `{{getvar::myvar}}` | 标准风格 |
| 多参 | `{{setvar::myvar::foo}}` | `::` 分隔多个位置参数 |
| 列表参数 | `{{random::a::b::c}}` | 注册 `list:true` 的宏可接任意数量 → `ctx.list` |
| 嵌套 | `{{if {{getvar::x}}...}}` | 参数内可嵌套宏（参数重新走宏模式 lexing） |
| 命名参数 | `name=value`（`=`/`"` 已被词法捕获） | **预留未实现**：`namedArgs` 恒为 null |
| 注释 | `{{// 任意文本}}` | 别名 `{{comment}}`；list+strictArgs=false，吃掉一切参数返回 '' |
| 输出过滤器 | `{{>macro ... | filter}}`（`>` flag + `\|`） | 语法已解析（Filter token），**功能未实现** |

### 2.2 Scoped 宏（成对块）

```
{{setvar::myvar}}  这里是内容  {{/setvar}}
```
- 开启宏 `{{name}}` + 内容 + 关闭宏 `{{/name}}`（`/` 为 CLOSING_BLOCK flag，关闭宏不带参数）；
- 求值前由 Walker 的 `#processScopedMacros` 配对，**内容作为最后一个 unnamed 参数**追加（等价 `{{setvar::myvar::内容}}`）；
- 配对规则：同名（大小写不敏感）匹配，支持嵌套（深度计数）；list 宏**不支持** scoped；参数数已满的宏不支持；无配对关闭宏 → 原样保留文本；
- **空白处理**：默认对 scoped 内容自动 `trimContent`（去首尾空白 + 按首非空行缩进**去缩进 dedent**）；加 `#` flag（PRESERVE_WHITESPACE）则保留原样；
- `{{if condition}}then{{else}}else{{/if}}` 是典型用法；`{{else}}` 返回不可见 `ELSE_MARKER`（`\u0000\u001FELSE\u001F\u0000`），由 `{{if}}` 的 handler 按最外层 else 拆分（`splitOnTopLevelElse`，用 Walker 的 `extractMacroInfo` 跟踪 if 嵌套深度）。

### 2.3 Flags（宏执行标志，位于 `{{` 与标识符之间，可组合）

| 符号 | 名称 | 状态 |
|---|---|---|
| `!` | immediate（立即解析） | 已定义，**未实现**（TBD） |
| `?` | delayed（延迟解析） | 已定义，**未实现**（TBD） |
| `~` | reevaluate（重新求值） | 已定义，**未实现**（TBD） |
| `>` | filter（管道过滤器开关，改变 `\|` 解析） | 语法已解析，功能**未实现** |
| `/` | closing block（关闭块） | **已实现**（scoped 配对） |
| `#` | preserve whitespace（保留空白） | **已实现**（阻止 scoped 自动 trim；兼容 handlebars `{{#if}}`） |

`{{!?myMacro}}`、`{{ ! ? myMacro }}` 均可（flag 之间允许空白）。

### 2.4 变量简写（Variable Shorthand，非宏）

- 前缀：`.` = 局部变量、`$` = 全局变量；
- 语法：`{{.var}}` / `{{$var}}` / `{{.var++}}` / `{{.var--}}` / `{{.var=值}}` / `{{.var+=值}}` / `{{.var-=值}}` / `{{.var||默认}}` / `{{.var??默认}}` / `{{.var||=值}}` / `{{.var??=值}}` / `{{.var==值}}` / `{{.var!=值}}` / `{{.var>值}}` / `{{.var>=值}}` / `{{.var<值}}` / `{{.var<=值}}`；
- 语义：`get / set / inc / dec / add / sub / logicalOr / nullishCoalescing / logicalOrAssign / nullishCoalescingAssign / equals / notEquals / 数值比较`；
- 值表达式**惰性求值**（只在实际需要时计算，缓存结果）；`=`/`+=` 等赋值操作返回空串；
- 变量标识符：`MACRO_VARIABLE_SHORTHAND_PATTERN` `/[a-zA-Z](?:[\w\-_]*[\w])?/`（允许中间连字符，但不能以 `-` 结尾，避免与 `--` 冲突）。

### 2.5 标识符与转义规则

- 宏标识符：`/^[a-zA-Z][\w-_]*$/`（字母开头，可含字母/数字/下划线/连字符）；大小写不敏感（注册 key 与查找都转小写）；
- 转义：`\{` / `\}` 写作文本，post-processor 统一去除反斜杠；
- 未知宏：保留原文 `{{...}}`（内部已解析的嵌套宏已替换）；
- 空输入直接返回 ''。

## 3. 按类别列出所有内置宏

> 注册入口 `initRegisterMacros()`（macro-system.js）顺序：core → env → state → chat → time → variable → instruct。
> `[可选]` 表示 optional 参数；`list` 表示可变长列表参数。

### 3.1 Utility（utility，core-macros.js）

| 宏 | 参数 | 作用 |
|---|---|---|
| `{{space}}` | `[count=1]` | 返回 count 个空格 |
| `{{newline}}` | `[count=1]` | 返回 count 个换行 `\n` |
| `{{noop}}` | — | 什么也不做，返回空串 |

## 4. 变量系统（Variables）

### 4.1 存储位置

| | 局部变量（local） | 全局变量（global） |
|---|---|---|
| 存储 | `chat_metadata.variables`（聊天元数据，随聊天存档） | `extension_settings.variables.global`（用户设置，跨聊天共享） |
| 持久化 | `saveMetadataDebounced()` | `saveSettingsDebounced()` |
| 生命周期 | 随聊天保存/删除 | 随用户设置保存 |
| 宏前缀/简写 | `{{getvar}}` 等 + `{{.var}}` | `{{getglobalvar}}` 等 + `{{$var}}` |

### 4.2 API

- 函数级 API（variables.js）：`get/set/add/increment/decrement/exists/delete` × Local/Global：
  - `getLocalVariable(name, args)` / `getGlobalVariable`：`args.key` 作为别名读取；`args.index` 支持对 JSON 数组/对象按下标/键取值；**数值字符串自动转 Number**；
  - `setLocalVariable(name, value, args)` / `setGlobalVariable`：`args.index` 时 JSON.parse 成数组/对象再赋值（`convertValueType(value, args.as)` 类型转换），否则直接存；返回 value；
  - `addLocalVariable` / `addGlobalVariable`：当前值是 JSON 数组 → push；否则值双方可解析为数值 → 数值相加；否则字符串拼接；
  - `increment*` / `decrement*`：即 `add(±1)`；
  - `exists*`：`存储[name] !== undefined`；
  - `delete*`：不存在时告警；删除后保存，返回 ''。
- 上下文 API（st-context.js 的 `SillyTavern.getContext().variables`）：
  - `variables.local = { get, set, del, add, inc, dec, has }`
  - `variables.global = { get, set, del, add, inc, dec, has }`
  - **新宏系统（variable-macros.js 与变量简写）都走这套 API**；旧宏系统走函数级 API。

### 4.3 数值 vs 字符串行为

- `get`：`trim()` 后为空或 `Number()` 为 NaN → 返回字符串（或 ''）；否则返回 **Number**（因此 `{{getvar::myint}}` 可直接参与数值运算）；
- `set`：原样存（不强制类型）；
- `add`：数值相加 > 字符串拼接 > 数组 push（优先级从高到低）；
- `inc/dec`：±1（`add(1)` / `add(-1)`）；
- 比较/逻辑（变量简写）：`==`/`!=` 字符串比较；`>`/`>=`/`<`/`<=` 数值比较（非数值时报运行时警告返回 'false'）；`||`/`??` 惰性求值默认值。

## 5. legacy macros.js（旧宏系统）与新系统关系

### 5.1 旧系统工作方式（正则替换）

- 核心 `evaluateMacros(content, env, postProcessFn)`：把一系列「正则 → 替换函数」分三批顺序执行：
  1. `preEnvMacros`（env 之前）：`<USER>/<BOT>/<CHAR>/<CHARIFNOTGROUP>/<GROUP>` 尖括号标记、掷骰、instruct 宏（`getInstructMacros`）、变量宏（`getVariableMacros`）、`newline/trim/noop/input`；
  2. `envMacros`：对 env 里每个键动态生成 `{{key}}` 正则（值可为字符串或函数，函数收到 nonce）；
  3. `postEnvMacros`：maxPrompt/maxContext/maxResponse、lastMessage 系列、reverse、`{{//}}` 注释、时间日期、outlet、timeDiff、banned、random、pick。
- 每轮 `content.replace(regex, ...)` 且结果过 `postProcessFn`；无 `{{` 时短路退出。
- `MacrosParser`（静态类）：`registerMacro/unregisterMacro/get/has/populateEnv/sanitizeMacroValue`，**已标记 @deprecated**，API 输出弃用警告并引导到新注册表。
- 局限性：正则模式各自为战、无嵌套、无 scoped、参数语法碎片化（如 `{{reverse:(.+?)}}` 单冒号、`{{roll[ : ](...)}}`）。

### 5.2 新旧关系（兼容桥）

- **开关**：`power_user.experimental_macro_engine`（User Settings → Experimental Macro Engine，默认 **true**）。
- **substituteParams 分流**（script.js）：传 options 对象且开关开启 → 新引擎（`MacroEnvBuilder.buildFromRawEnv` + `MacroEngine.evaluate`）；否则 → `substituteParamsLegacy` → `evaluateMacros`。旧式位置参数签名会自动路由到 legacy。
- **注册桥接**：`MacrosParser.registerMacro` 在开关开启时同步注册到新 Registry（`category:'legacy'`，0 参数 handler，函数值用 uuidv4 nonce 调用——与新引擎 `dynamicMacros` 语义对齐）；迭代宏列表/`has` 在开关开启时也读新注册表。
- **旧语法由引擎的 pre/post-processors 兼容**（新引擎内完成 legacy 兜底）：
  - pre：`<USER>`→`{{user}}`、`<BOT>/<CHAR>`→`{{char}}`、`<GROUP>`→`{{group}}`、`<CHARIFNOTGROUP>`→`{{charIfNotGroup}}`；`{{time_UTC±N}}`→`{{time::UTC±N}}`；
  - post：`\{ \}` 解除转义；删除 `{{trim}}` 及其周围换行；清理 `ELSE_MARKER` 残留。
- **initMacros()**（macros.js）：仅当开关关闭时注册 `isMobile`、`lastGenerationType`（旧引擎独有宏）；无论开关与否都调用 `initRegisterMacros()` 注册全部新内置宏（新引擎定义始终就绪）。
- **新宏覆盖旧宏**：`{{random}}`/`{{pick}}`/`{{roll}}`/`{{time}}`/`{{reverse}}`/`{{banned}}` 等在新注册表中都有等价实现，并兼容旧调用写法（`{{random:a,b}}` 逗号列表、`{{roll 1d6}}` 空格、`{{roll:1d6}}` 冒号）；`{{hasvar}}/{{deletevar}}`（含 global 版）是**新系统新增**（旧正则集没有）。
- **变量宏双轨**：旧系统在 `getVariableMacros()` 用正则直接调 `setLocalVariable` 等函数；新系统在 `variable-macros.js` 统一走 `ctx.variables.local/global` 对象方法。
