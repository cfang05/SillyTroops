**无限旅团（SillyTroops）** 是一套以 uni-app（Vue 3）构建的 AI 跑团 / 酒馆式角色扮演应用。它把「角色卡 → 世界书 → 预设 → 正则 → 变量宏 → 对话存档」这一整套酒馆生态搬进一个统一的产品里，在其上叠加了一套原创的 TRPG 玩法层（骰子、背包、人物特性、传奇物品、等级与经验），并配套一个同仓部署的 Express 后端：负责账号与权限、使用统计、卡池社区数据，以及把浏览器发来的 LLM 请求安全地代理到各家模型服务。

前端同时面向 **H5（手机浏览器）** 与 **微信小程序** 两个目标。后端与首页视觉均按「画布限宽 480px 的手机 H5」设计，桌面宽屏下保持手机比例居中呈现。

> 微信小程序适配目前因为环境约束太多，暂定缓行；本文档默认以 H5 为主叙述，涉及小程序端的差异会单独标注。

## 项目定位

市面上的酒馆前端大多把「角色卡、世界书、预设、正则、变量宏」实现为彼此独立的功能点，玩家要在多个页面之间来回搬运配置；而跑团玩法（属性、骰子、背包、成长）又往往只存在于聊天文本里，说完就忘。

无限旅团要解决的是这两件事的合流：

1. **配置一次，全局生效。** 角色卡、世界书、预设、正则脚本、Persona 各有明确的作用域规则（全局 / 跨预设 / 单次对话），互相合并而不是互相覆盖。
2. **让跑团状态成为结构化数据，而不是聊天记录。** 骰子结果、背包物品、人物特性、角色属性、等级经验都是可读写的对象，能进提示词、能渲染成面板、能跨设备同步、能在评论里显示。

配套后端的定位是「薄而必要」：前端坚持本地优先（对话与配置默认存在浏览器里），后端只承担**必须共享**的部分——账号身份、权限判定、使用统计、卡池全局数据，以及一个不把 API Key 暴露在前端的 LLM 转发代理。

## 核心特性

### 一、酒馆生态兼容

- **角色卡导入（JSON / PNG）。** 支持酒馆 V2 角色卡格式；PNG 卡从图片元数据中解出卡片数据（H5 端）。导入时**世界书随卡一起导入**并绑定到该角色，无需二次操作。项目另内置两张可直接使用的角色卡，在新建对话时按需选择，不会自动写进用户数据。
- **世界书（Lorebook）引擎。** 完整的关键词触发语义：主键 / 次键、大小写与整词匹配、递归扫描、概率触发、分组与优先级、token 预算裁剪、`minDepth`/`maxDepth` 深度过滤。扫描结果按 `before` / `after` / `atDepth` 三个桶产出，交由提示词构建器按位置注入。
- **预设（Preset）系统。** 对齐酒馆 PromptManager 的 `promptOrder` 语义，支持 marker 提示词（`charDescription`、`charPersonality`、`scenario`、`dialogueExamples`、`personaDescription`、`worldInfoBefore`、`worldInfoAfter` 等）以及 `injection_position` 的 `RELATIVE`（系统块内按序）与 `ABSOLUTE`（按 `injectionDepth` 注入历史深处）两种注入模式，`system_prompt` / `post_history_instructions` 分别覆盖 main 与 jailbreak。
- **正则脚本（正侧）。** 按酒馆逻辑分三路来源**合并生效、互不覆盖**：全局正侧（跨角色、跨预设常驻）、预设自带正侧、新建对话时额外勾选的正侧。支持 `markdownOnly` / `promptOnly` 标志，正则编辑页可直接增删改。
- **Persona（我的角色）。** 管理用户自身在故事中的身份与设定，支持 TRPG 档案，并按角色卡绑定不同的出场人格。
- **变量与宏系统。** 支持 `{{user}}`、`{{char}}`、`{{persona}}` 等标准宏，以及对话历史类宏 `{{lastMessage}}`、`{{lastUserMessage}}`、`{{lastCharMessage}}`、`{{firstMessage}}`；支持变量读写与局部/全局作用域，世界书条目内同样参与宏替换。
- **酒馆资源导入页。** 卡片、正侧、预设集中在「酒馆导入」一个入口内完成，导入结果就地展示（含「N 条世界书」这类解析反馈）。

### 二、TRPG 玩法层（功能开发中）

> ⚠️ 本模块仍在开发中，下述能力尚未全部完成与定型，接口、数据格式与交互均可能调整。默认以 H5 端为主要验证环境。

- **骰子快捷栏。** 计划支持常见骰式与检定，掷骰结果作为结构化数据进入对话与提示词，而不是纯文本。
- **背包与物品系统。** 物品具有类型、效果、数量与使用逻辑，内置通用物品表，装备与消耗品可被剧情与提示词共同引用。
- **人物特性与传奇收藏。** 「传奇收藏」页分「人物特性」「传奇物品」两个签页，未解锁条目以 `???` 呈现，构成收集与成长反馈。
- **角色属性与战斗面板。** 角色状态、数值系统、战斗面板、任务/剧情可作为独立模块开关，按需显示在对话中。
- **等级与经验系统。** 等级为账号属性、跨设备同步；升级所需经验按 `floor(100 × (1 + level × 0.15))` 计算，1–20 级对应一套自洽的称号体系，超出范围回落到「未启程者 / 不可名状者」。

### 三、对话与渲染

- **流式输出与节奏控制。** SSE 逐字透传，配合可配置的平滑输出（字/秒档位），并可独立开关模型思考（reasoning）内容。
- **富块解析与渲染。** 统一的块解析器把模型输出拆成类型化区块：选项分支按钮、摘要卡片、时间卡片、自定义 HTML（H5）、音乐播放器、推理块，以及降级纯文本。
- **上下文检查器。** 可视化查看这一轮实际发往模型的完整消息栈与世界书命中情况，用于排查「为什么模型这样回答」。
- **意图识别。** 可选的意图解析，把自然语言指令映射到玩法动作（掷骰、查看背包等）。
- **跨端存储与大数据量。** 对话存档 H5 端走 IndexedDB，小程序端走本地存储；角色卡、预设、Persona 等经统一缓存层管理。存储层被抽象成可替换的适配器接口，为后续远端同步预留位置。
- **一键备份与恢复。** 导出/导入覆盖对话存档与全部本地配置，备份文件带 schema 版本号并向后兼容。H5 端走文件下载/选择，非 H5 端降级为剪贴板。
- **自定义 CSS 与多媒体。** 支持注入自定义样式；页面支持视频背景与海报图。

### 四、卡池与社区

- **冒险卡池。** 分「角色卡 / 冒险卡 / 预设·正则」三类浏览，支持筛选抽屉、卡片详情、评分与下载。
- **评分。** 1–5 分并支持**半星**（0.5 的整数倍），评分口径为 `ratingSum / ratingCount` 保留一位小数，无评分时显示「暂无评分」。同一用户改评分只调整总分、不重复计数。
- **评论。** 发表与删除均需登录，评论者身份与等级一律取自服务端登录态；评论展示**当前**等级（等级存在数据库，读取时覆盖快照值）。
- **卡池导入。** 从卡池导入的卡片会在角色卡库与选择页同时显示「新导入」标识（24 小时内），并记录来源卡片 id 以判断是否已导入。
- **等级榜。** 按等级倒序、同级按经验倒序的公开榜单接口，供社区类页面使用。

### 五、账号、权限与统计

- **服务端账号体系。** 注册 / 登录 / 改昵称 / 认领老本地账号，密码以 `scrypt` + 每账号独立 salt 哈希入库，明文永不落库、永不返回前端；前端只保存签名 token 与脱敏用户信息。登录态带 `token_version`，管理员重置密码后旧 token 立即失效。
- **注册规则（站点公开后）。** 昵称**必填**且**全站唯一**（大小写不敏感，改昵称走同一套校验），避免大量空昵称与重名冒充。注册的新账号**默认没有测试权限**（`is_test = false`）：能否使用内置测试通道由管理员在监控页「测试管理」里逐个开启，下一次请求即生效；请求体里伪造 `isAdmin/isTest` 一律被忽略。存量账号的 `is_test` 保持不变，收回权限由管理员逐个关闭。
- **服务端裁决的权限。** 能否使用内置测试通道由数据库中的 `is_admin || is_test` 决定，客户端无法自授。公开的「认领老账号」接口也**不带来任何权限**（`isAdmin/isTest` 恒为 false），否则等于给了一条自封管理员的后门。
- **老数据迁移。** 迁移前存在于浏览器本地、含明文密码的老账号，首次登录时用本地旧密码校验通过后自动「认领」到服务端；历史用量以 `GREATEST` 语义一次性导入，重复导入不会翻倍。老账号沿用原有 `user_*` id，保证历史业务数据仍可读取。
- **使用统计。** 累计表与按天表双写，按 **Asia/Shanghai** 切分日期；时长口径为**活跃时长**（仅在真实交互时累计，空闲 5 分钟以上不计、切后台不计），监控页总时长为历史老口径值与新活跃时长之和。
- **监控页。** 管理员可查看用户总数、今日活跃、总时长、token 用量与登录事件流水，并支持按天与按用户维度查询。

### 六、模型接入

- **内置测试通道（Key 不出服务端）。** 前端只声明「我要用测试通道」，Key、目标地址、模型名与协议参数全部由服务端持有。官方改模型名时只需改服务端变量，前端无需改代码或重新发版。采样参数（`temperature`、`max_tokens`、`top_p`、`top_k`、`presence_penalty`、`frequency_penalty`、`seed`、`n`、`stream_options`）由前端预设决定并原样透传；针对 DeepSeek 系目标，服务端会自动注入 `thinking: { type: 'disabled' }` 等协议参数。
- **用户自配 Key 通道。** 支持腾讯混元、OpenAI GPT、Claude 以及任意 OpenAI 兼容端点。H5 下前端不直接跨域请求，而是把配置放进 `X-API-Base` / `X-API-Key` 请求头交给同源后端代理；小程序端没有 `/api` 代理，直接调用真实 API。
- **服务端代理。** `/api/*` 默认转发到用户指定或环境变量指定的 OpenAI 兼容目标，SSE 响应边收边写不做缓冲，客户端断开（停止生成 / 关闭页面）时立刻中断上游以免继续计费。代理路径**刻意跳过** JSON 解析，避免请求体被消费导致上游空 body。
- **小程序内置模型。** 小程序端可走云端内置的腾讯混元模型，无需用户自配 Key。

### 七、前端工程基础

- **双端条件编译。** 通过 `#ifdef H5` / `#ifndef MP-WEIXIN` 等条件编译隔离平台专有依赖（如 `js-tiktoken`、自定义 HTML 渲染），保证小程序端打包不引入 Web 专属库。
- **真实 tokenizer 与估算双轨。** H5 端接入 `js-tiktoken`（`cl100k_base`）做真实 token 计数，小程序端保留启发式估算。
- **调试与可观测。** 内置调试日志与调试页，支持查看提示词构建、世界书命中、正则改写过程。
- **设计令牌体系。** 全站颜色基于 OKLCh 色彩空间的令牌，配合毛玻璃面板、发丝线边框与模块强调色，形成统一的暗金幻想风格。

## 设计规范

- **色彩：** 基于 OKLCh 令牌，暖调近黑背景（`oklch(17% 0.012 70)`）配琥珀金强调色（`oklch(81% 0.13 84)`）；遵循「一屏一强调」，品牌金只用于激活态、主 CTA 与等级/奖励。
- **字体：** 展示标题用衬线，正文与导航用无衬线，等宽字体仅用于数值与技术性眉题。
- **质感：** 毛玻璃面板 + 发丝线边框优先，阴影只留给弹层与主 CTA；图标统一内联 SVG 线性描边。
- **布局：** 内容整体限宽 480px 居中，宽屏以更深的背景填充两侧，保持手机比例不变形。
- **无障碍：** 可聚焦元素必须有 `:focus-visible` 焦点环；`prefers-reduced-motion` 下关闭位移与滚动动画。

完整规范见 `notes/brand-spec.md`。

## 安全与隐私

- **密钥不落前端：** 内置测试 Key 只存在于服务端；用户自配 Key 仅经请求头传给同源代理，代理不存储、不记录，并在转发前剥离自定义头，避免泄露给第三方模型服务。
- **密码学存储：** 密码以 `scrypt` + 每账号独立 salt 哈希入库，明文永不落库、永不返回前端。
- **服务端裁决的授权：** 测试通道权限、评论署名、用量归属全部以服务端 token 与数据库为准，客户端无法自授权限或伪造他人数据。
- **登录态撤销：** 账号带 `token_version`，管理员重置密码即令所有旧 token 立即失效。
- **数据最小化：** 统计只记录活跃时长、token 计数与登录事件，不记录对话内容本身。

> 本项目会采集账号信息（用户名、昵称）与使用统计（活跃时长、token 用量、登录事件），存于部署方自有的 PostgreSQL 实例，用于登录鉴权、用量统计与管理监控；对话内容与模型凭据默认保存在用户自己的浏览器/设备本地。

## 常见问题

- **登录接口返回 503：** 服务端未配置数据库连接串。账号与统计功能依赖 PostgreSQL，其余功能不受影响。
- **卡池评分 / 评论返回 503：** R2 凭证缺少任意一项。注意凭证容易粘入首尾空白或换行。
- **服务启动直接退出：** 生产环境缺少 `AUTH_SECRET` 会拒绝启动；本地开发会使用临时密钥，重启即导致登录态失效。
- **内置测试通道不可用：** 依次确认测试通道开关未关闭、服务端已配置 Key、当前账号具备测试权限。小程序端不支持该通道，必须自配 Key。
- **流式输出卡住、日志出现 `ECONNRESET`：** 通常是代理路径的请求体被提前解析。新增本地接口时必须把前缀加入服务端白名单，其余 `/api/*` 一律交给代理。
- **页面仍是旧版本：** 前端产物需在本地构建后随仓库提交，部署时不会重新构建前端。

## 开发约定

- **双端兼容是硬约束：** 新增代码必须在 H5 与微信小程序两端都能编译通过，平台专属能力一律用条件编译隔离。
- **存储只用跨端 API：** 统一走项目封装层，禁止直接使用 `localStorage`、`sessionStorage`、`wx.setStorage`。
- **模板单根节点：** `template` 下必须只有一个根节点，否则页面白屏。
- **全局对象只读数据：** 只使用 `getApp().globalData.xxx`，不依赖挂在实例上的普通方法。
- **新增本地接口必须同步服务端白名单**，否则请求体不会被解析且会被误转发到模型上游。
- **改动前端后必须本地构建并提交产物**，否则线上仍是旧版本。
- **设计令牌优先：** 页面颜色取自设计令牌，不硬编码十六进制；正文与导航不使用等宽字体。
- **布局自检：** 内容区左右留白对称、横向排列元素超宽换行、`flex: 1` 且 `white-space: nowrap` 的子项必须加 `min-width: 0`。
